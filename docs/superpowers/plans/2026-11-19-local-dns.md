# Local DNS service implementation plan

Goal: a bounded Windows loopback DNS forwarder using the existing parser and lists.

Architecture: Winsock on Windows and POSIX sockets for independent Linux testing.
DNSProxy owns bound UDP/TCP listeners, a bounded job queue and fixed workers.
Each upstream exchange uses a connected socket, secure random ID and a deadline.
Existing parser/domain-list APIs remain intact. No adapter settings change on startup.

- [x] Phase 1: DNSProxy.hpp/.cpp, numeric IPv4 configuration, UDP validation and
  forwarding. Test local fake upstream, malformed messages, timeout and mismatches.
- [x] Phase 2: TCP framing, fixed worker/queue limits, stop-token shutdown, UDP TC
  fallback. Test concurrent identical IDs, split frames, unavailable upstream.
- [x] Phase 3: domain-list integration, allow precedence, REFUSED response.
  Test that block never reaches fake upstream, allow/subdomain decisions.
- [x] Phase 4: key=value config, bounded list/config files, strict validation and
  sample config. Test invalid values, duplicate keys and non-loopback binding.
- [x] Phase 5: console/SCM host, opt-in install and reversible adapter procedure.
  Build on MSVC/MinGW; run unprivileged loopback 5353 tests before any port 53 use.
- [x] Phase 6: official browser documentation, Secure DNS verification limitations.
- [x] Final: full CTest, network integration tests and sanitizer run. Record actual
  results and remaining Windows policy blocks.

Resource decisions: workers 1..32, queue 1..256; timeout 100..10000 ms;
single question standard QUERY, maximum wire message 65535; UDP client responses
limited to min(client EDNS size,4096), minimum 512. TCP connections handle at most
16 messages with one overall timeout to prevent indefinitely held workers.
Review focus: identical transaction IDs, stop during slow upstream, partial TCP,
strict response source/question matching, and domain-list load errors.

Windows service deployment and native/browser runtime remain unverified due to Application Control. See docs/DNSServiceValidation.md for actual results.
